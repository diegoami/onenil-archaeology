## Placement order and temporary counts

`[confirmed]` The outer side visits 0 then 1. It enters the fill/scan body only
when that side's unsigned generated byte exceeds its saved score (`DD86`–`DD95`).
It subtracts the saved score from **only that selected generated byte**
(`DD98`–`DDA1`), then fills the minute tables for both sides in side/goal-index
order. A second entered outer pass fills both tables again, using the counts as
they then stand. There is no sorting or deduplication.

Each fill asks the original generator for `random(minute_limit)` at return site
`DDE4` and stores its low byte. The address is
`SS:BP + 11*one_based_side + one_based_goal_index - 0x26` (`DDE6`–`DDEF`).
For counts at most 11, side 0 occupies `BP-1Ah..BP-10h` and side 1 occupies
`BP-0Fh..BP-5`; neither overlaps the other locals. Larger counts can alias another
table or frame field. DD02's ordinary chance-table inputs 8/11 bound the generated
counts; the supported bounded translation domain is `generated <= 11` per side.
Rejecting an unsupported input is a translation diagnostic, not a claim that the
original safely handles arbitrary overflowing frame writes.

The scan visits side 0 then 1, in increasing goal index (`DE00`–`DE26`). It selects
a candidate only while the local goal flag is zero, its zero-extended minute
byte equals the **full word** elapsed value, and that side's unsigned saved score
is below 15 (`DE29`–`DE52`). Elapsed values must not be narrowed to a byte: `0x0101`
does not equal generated minute 1.

## Eligibility, first roster match and actor

`[confirmed]` A scorer draw requests `random(30)` at return site `DE5C`. Its result
1–30 selects the corresponding byte of the scorer-slot table; that 1-based slot
selects a word from the chosen club roster (`DE55`–`DE89`). Selection retries when
`1B55:4F89` returns nonzero.

`4F89` returns the following unavailable predicate (`4F9D`–`5008`):

```text
player_id == 0
or signed(player_byte_8) < 1
or (player_status_byte_11 & 0xA6) != 0
```

The tested bit numbers 8/6/2/3 are **one-based**: `24BC:025D`–`026A` subtracts
one before shifting, giving masks `0x80/0x20/0x02/0x04`. No football injury or
suspension name is assigned to those bits. `0AB9:1CA1` loads a scene record's
player ID at `+0Eh`, calls `4F89`, and returns AL unchanged (`1CA5`–`1CB8`). Thus
the scene-predicate observations in T12 are checks of the same eligibility helper.

On acceptance, the selected saved score increments (`DE96`–`DE99`). The guard
permits reaching 15; it is separate from the scorer-log count cap 11 in `5083`.
`1B55:5C6E` searches the roster's 20 words and returns the first matching position
1–20, or zero when absent (`5C81`–`5CA6`). Duplicate IDs must choose the first
match. The helper itself does not reject player zero: a query for zero can find
the first zero roster word, although scorer eligibility separately rejects it.

The low byte of `first_position + side_offset` becomes `DS:D09F`
(`DED4`–`DEEA`). The goal event passed to `5083` contains the minute word, actor
word and side flag; semantically the actor is a byte, and side flags are 1/0 for
model sides 0/1 (`DEED`–`DF0C`). Full scratch-register/high-byte equality is not
part of this contract.

## Goal callback, RNG projection and outputs

`[confirmed]` `5083` unconditionally calls `24BC:0D3F` at `518B`, with return site
`5190`: one underlying `random(2)` draw. Its direct-call closure contains no
indirect calls and no other RNG entry. In the ordinary valid, disjoint game-data
layout it does not write the placement's generated bytes, saved-score frame,
actor `D09F`, or seed pointer `DE84`; its seed change is this generator call.
`D09F` is read by `1DB7` at `1DBE`, and the DD02 frame is not passed to `5083`.
The clamp pointer used by `67D0` points into that callee's own frame (`67F0`–`67FD`).

After the callback returns, DD02 sets its local goal flag to 1 and forces the
outer index to 2 (`DF0F`–`DF13`). All later candidates skip the goal path and the
outer loop exits: at most one goal callback occurs. A no-goal placement leaves
the entry actor byte unchanged.

`[designed]` The bounded Rust slice computes the unconditional coin draw itself
from its live seed, with argument 2 and site `5190`. Expected callback draws or
precomputed output seeds must not control that computation. Player statistics,
scorer logs, commentary/display state and the remaining callback effects stay
explicit external effects, not an implicit no-op or a claim of translated `5083`.

The block's outputs are the final seed, **residual generated bytes**, mutable
saved scores, goal flag, actor byte, optional computed goal event, and ordered
draw/decision trace. At `DF35` the global generated bytes have not yet been
replaced with saved scores; the replacement and byte swap occur at `DF35`–`DF40`.
Do not normalize residual generated counts or substitute cumulative scores for
them at the earlier boundary.

# T04 Runtime: drive One-Nil 96 under DOSBox-X, and does it load a saved game

- **Kind**: runtime
- **Issue**: #7 · **Branch**: `task/T04-runtime` · **Merge after**: T02
- **Evidence**: F01 item 4 (TP7 Crt's delay calibration: runtime error 200 on a fast CPU), F02 items
  11–13 (96's limited-build texts switched off: `[derived]`, a run decides), CLAUDE.md rule 16.
  goal2-archaeology's driver (`runtime/driver/{driver,savestate,xkeys,cycle}.py` at 774473eb,
  its F001/F003) on DOSBox-X 2024.03.01 (`~/tools/dosbox-x-2024.03.01`), Xvfb, xdotool. Claims
  are `[confirmed]` by run records; finding `F04`.
- **Owns**: `runtime/**`, `setup/**`, `tests/runtime/**`, `runs/T04/**`, `findings/F04-*`,
  `docs/environment.md`.
- **Scope**: the claim: *an agent can launch 96, act, observe and reset it, and 96 loads a save*.
  - Port goal2's driver: launch headless (Xvfb), keys in (raw XTEST), the screen read from a
    savestate's video memory (text page, or the mode and its bytes' digest if the game draws in a
    graphics mode: find out which), savestate and restore, terminate. Game files copied from
    `.cache/One-Nil96/` into a session folder, never run in place.
  - `setup/onenil-runtime.sh`: checks the tools and versions, prints `ready` or what is missing.
  - The emulated speed: `cycles` fixed (not `max`), chosen so Crt's calibration does not overflow;
    record the value and that runtime error 200 does not appear.
  - A cycle tool: restore → key → screen → reset, one run record per cycle under `runs/T04/`.
  - **The save**: launch 96, answer yes to "Do you want to load a saved game", load `SAVE1.1-0`,
    and record the screen after loading; then advance the game week by week (the weekly menu's
    continue) for 10 weeks, recording each week's screen, and whether any shows the registration
    text.
  - **Out of scope**: the emulator harness (Unicorn), match traces, reading memory fields.
- **Milestones**: (1) setup and launch to the first screen; (2) the cycle and its records; (3) the
  save loaded and 10 weeks; (4) F04.
- **Done when**:
  1. `bash setup/onenil-runtime.sh` prints `ready`.
  2. `python3 runtime/driver/cycle.py --runs 10 --start-state title` writes 10 records under
     `runs/T04/`, all with the same before-screen digest, and `python3 runtime/validate.py runs/T04`
     exits 0.
  3. A record under `runs/T04/` shows 96 past the load question with `SAVE1.1-0` loaded (the game's
     own screen after loading, not the purchase message), and 10 week records follow it.
  4. `findings/F04-runtime.md` exists, status `proposed`, and states for F02 items 11–13 what the
     run showed.
  5. `python3 tools/check_originals.py` exits 0, and no savestate or game byte is tracked.
- **Hazards**: a savestate holds the game's memory: it goes to the owner's Drive
  (`python3 tools/artifacts.py push`), never to git; records hold its sha256. goal2's driver
  assumes GOAL's text screens and file names: check every assumption against One-Nil.
